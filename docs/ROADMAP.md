# 機能追加案と実装方針

Obsidianがなぜ使われているのかをUI/UXの観点で整理し、そこからRobsidianに足すべき機能を、
実装方法とセットでまとめたものです。コードの場所は現在の構成（`crates/core`・`crates/cli`・`crates/app`）を前提にしています。

規模の目安: **S** = 1〜2日、**M** = 1週間前後、**L** = 数週間以上（設計の試行錯誤を含む）。

---

## 1. Obsidianはなぜ使われているのか

機能の多さではなく、次の5つの「体験」が理由だと考えます。

### 1-1. データが自分のものだという安心感

ノートは手元のフォルダにあるただのMarkdownです。アプリが消えても読め、gitや任意の同期手段に載せられます。
「10年後も読める」ことが、長く書き溜める道具としての信頼の土台になっています。

- UX上の意味: 乗り換えコストへの不安がないので、最初の一歩が軽い。
- Robsidianの現状: 同じ形式をそのまま読み書きするので、この価値は引き継げています。

### 1-2. 書く流れを止めない

- **Live Preview**: 記法を打つとその場で整形され、カーソルのある所だけ記法が見える。Markdownを知らない人が残る最大の理由です。
- **編集の小さな親切**: リストの自動継続、チェックボックスのクリック、括弧の自動補完、画像の貼り付け。
- **即座に書き始められる**: デイリーノート、テンプレート、クイックスイッチャーからの新規作成。

Robsidianの現状: クイックスイッチャー、デイリーノート、Live Preview（基本要素）はある。編集の親切・テンプレートがない。
**ここが「毎日使う気になるか」を最も左右する差です。**

### 1-3. リンクが「発見」を生む

`[[リンク]]` を書くだけでバックリンクが付き、まだリンクしていない言及（Unlinked mentions）も拾われ、
リンクにカーソルを載せると中身が覗けます（Page preview）。書いたものが勝手に繋がっていく感覚が、続ける動機になります。

Robsidianの現状: リンク・バックリンク・グラフ・改名追従はある。未リンクの言及、ホバープレビュー、見出しへのリンク、埋め込み（transclusion）がない。

### 1-4. 自分の場所を見失わない

タブ、ペイン分割、戻る/進む、ブックマーク、最近開いたファイル、アウトライン。
「さっき見ていたあれ」にすぐ戻れることが、大きなvaultでの快適さを決めます。

Robsidianの現状: タブとアウトラインのみ。戻る/進む、ブックマーク、ペイン分割がない。

### 1-5. 自分の道具に育てられる

プラグインとテーマで、タスク管理にも、データベースにも、執筆環境にもなります。
ただし実際によく使われているのは一握りの用途です（クエリ表示、タスク集約、テンプレート、カレンダー、かんばん）。

Robsidianの現状: 拡張の仕組みはなし。エコシステムの量で追いつくことは現実的ではないので、
「よく使われる用途を本体に持つ」「シェルから拡張できる」方向で応えるのが筋だと考えます。

### Obsidianが苦手なところ（差別化の余地）

| 苦手なこと | Robsidianでの機会 |
|---|---|
| 起動とメモリが重い（Electron）。大きなvaultで顕著 | ネイティブ単一バイナリ。保存時は差分だけ索引し直す（案C1） |
| プラグインはvaultとPC全体に無制限にアクセスできる | 権限を絞った拡張、またはシェルコマンド連携（案C4。実行前に内容を見せて許可を取る） |
| タスクやクエリなど基本的な用途が外部プラグイン頼み | 本体とCLIに標準搭載（案B5） |
| アプリを開かずにvaultを機械的に扱う手段が弱い | 単体で動くCLIを自動化の入口にする（案C2） |
| 版管理・復元は有料の同期サービスか別プラグイン | ローカルスナップショットとgit連携（案C3） |

## 3. フェーズA: 日常の摩擦を消す

### A1. 編集の親切（実装済み）

**実装した内容**

- 編集操作は `crates/app/src/edit.rs` の純粋関数（本文と選択範囲 → 置き換え）。`|` と `«»` でカーソル・選択を書いたテキストでテストしている。
  - Enter: `-`・`*`・`+`・`- [ ]`・`1.`・`1)`・`>` を次の行に継続。空の項目では記号を外す（入れ子なら1段浅く）。コードブロック内は対象外。
  - Tab / Shift+Tab: リスト項目、または複数行の選択を字下げ / 字上げ。字下げの単位は文書から判定（タブ、または行頭の空白幅。既定はタブ）。
  - Ctrl+L: チェックボックスを付ける / 切り替える。Ctrl+B / Ctrl+I: `**` / `*` で囲む、囲まれていれば外す。
  - 選択中に `( [ { " ` * _ = ~` を打つと囲む。`(` `[` は閉じ括弧を補い、直後の閉じ括弧は上書きして進む（`[` を2回で `[[]]` になり、そのままリンク補完につながる）。
  - URLを選択範囲に貼ると `[選択](URL)`。
- 画像の貼り付けはeguiの `PasteImage` を受けてPNGで保存（`Vault::attachment_path` が `.obsidian/app.json` の `attachmentFolderPath` に従う）し、`![[Pasted image 日時.png]]` を挿入する。
- 左サイドバーの切り替えは Ctrl+B から Ctrl+\\ に移した。

**実装上の注意**

- キーはTextEditより先に取り出す（`app.rs` の `take_edit_event`）。同じフレームで先に本文を変える入力があると順序が崩れるため、その入力以降を次のフレームへ回す。
- 変更前の状態を TextEdit の undoer に `add_undo` で積むので、Ctrl+Z / Ctrl+Shift+Z がそのまま効く。Live Previewのチェックボックスのクリックも同じ仕組みで戻せる。
- IMEの変換中（Preeditが空でない間）は、Enter・Tabを編集補助の対象にしない。日本語IMEの実機確認は未実施。
- 以前は eframe の `clipboard` 機能を無効にしていたため、コピー＆ペースト自体が効いていなかった。有効にした。

以下は着手前に書いた設計メモ。


**狙い**: いまのエディタは「色の付いたテキストエリア」です。書くたびに小さな手間が積もり、Obsidianに戻る理由になります。

**仕様**

- Enterでリスト・番号リスト・チェックリスト・引用を継続。空の項目でEnterを押すとリストを抜ける。
- Tab / Shift+Tab でリスト項目のインデントを増減。
- `[[`・`(`・`` ` ``・`**` の自動補完と、選択範囲の囲み。
- Ctrl+L でチェックボックスの切り替え、Ctrl+B / Ctrl+I で太字・斜体。
  （現在 Ctrl+B は左サイドバーに割り当てているので、サイドバーを Ctrl+\ などに移す。）
- URLを選択範囲に貼ると `[選択](URL)` になる。
- クリップボードの画像を貼ると、添付フォルダに保存して `![[画像名.png]]` を挿入。

**実装**

- `crates/app/src/editor.rs` に、純粋関数として編集操作を足す。

  ```rust
  pub struct Edit { pub range: Range<usize>, pub insert: String, pub cursor: usize }
  pub fn on_enter(text: &str, cursor: usize) -> Option<Edit>;
  pub fn on_tab(text: &str, sel: Range<usize>, outdent: bool) -> Option<Edit>;
  pub fn toggle_checkbox(text: &str, cursor: usize) -> Option<Edit>;
  pub fn wrap_selection(text: &str, sel: Range<usize>, open: &str, close: &str) -> Edit;
  ```

  純粋関数にしておくと、GUIなしで単体テストが書けます（既存の `link_at` などと同じ方針）。
- `app.rs` の `editor_ui` では、`[[` 補完と同じやり方で **TextEditに渡る前にキーを消費**し
  （`ctx.input_mut(|i| i.consume_key(..))`）、返ってきた `Edit` を `tab.text` に適用して
  `TextEditState` のカーソルを更新する。適用処理は補完の確定処理と共通化する。
- 画像貼り付け: `arboard` クレートでクリップボードの画像を取得し、既に依存にある `image` でPNGに書き出す。
  保存先は `.obsidian/app.json` の `attachmentFolderPath` があればそれに従い、無ければノートと同じフォルダ。
  保存後は `vault.rescan()` ではなく、添付ファイル1件を索引に足すメソッドを `Vault` に追加する。

**注意**: 元に戻す（Ctrl+Z）はeguiのTextEditが内部で持っているため、外から文字列を書き換えると履歴に載りません。
最初は `tab.text` 書き換えの直前の状態を自前のスタックに積む簡易実装で始め、B2で自前の編集基盤を持つ段階で統合します。

### A2. テンプレート（実装済み）

**実装した内容**: `crates/core/src/template.rs`（`{{title}}`・`{{date}}`・`{{time}}`・`{{date:書式}}`、moment.js形式の書式）、
`Vault::templates`・`find_template`・`render_template`。デイリーノートは `.obsidian/daily-notes.json` の `template` を新規作成時に展開し、
日付の書式も同じ実装に統一した。GUIはコマンド「テンプレートを挿入」「テンプレートから新規ノート」、CLIは `rob new -t` と `rob templates`。
知らない変数（`{{...}}`）は他のプラグイン向けの可能性があるので、そのまま残す。

以下は着手前の設計メモ。


**狙い**: 「書き始めるまでの手数」を減らす。デイリーノートが毎回白紙なのは続かない原因になります。

**仕様**

- テンプレート置き場は `.obsidian/templates.json` の `folder`、無ければ `templates/`。
- 変数は `{{date}}`・`{{time}}`・`{{title}}`、および `{{date:YYYY-MM-DD}}` 形式。
- デイリーノートは `.obsidian/daily-notes.json` の `template` を自動適用。
- コマンドパレットに「テンプレートを挿入」「テンプレートから新規ノート」。
- CLI: `rob new <名前> --template <テンプレート名>`。

**実装**

- `crates/core/src/template.rs` を新設。`render(template: &str, title: &str, now: DateTime<Local>) -> String`。
  日付書式は `vault.rs` の `daily_path` にある YYYY/MM/DD 置換を関数に切り出して共用する。
- `Vault::daily()` で、新規作成時だけテンプレートを読み込んで本文にする。
- GUIは既存の `Palette` に「テンプレート選択」モードを足す（`PaletteItem::Template(String)`）。

### A3. 見出しへのリンク（実装済み）

**実装した内容**: `[[ノート#見出し]]`・`[[#見出し]]`（同じノート）を辿ると、その見出しの行へ移動する（`a#b` のような入れ子は最後の見出しで探す）。
`[[ノート#` まで打つと、そのノートの見出しを階層付きで補完する。プレビューのリンクも見出しへ移動する。

以下は着手前の設計メモ。


**狙い**: `[[ノート#見出し]]` は書けるのに、開くと先頭に飛ぶだけです（`follow_link` で `#` 以降を捨てている）。

**実装**

- `app.rs` の `follow_link` で `#` 以降を保持し、解決したノートの `parsed.headings` から一致する見出しの行を探して
  `open_note(path, Some(line))` に渡す。既存の行ジャンプがそのまま使える。
- `editor::completion_start` を拡張し、`[[ノート名#` まで打った状態を検出して、そのノートの見出しを候補に出す。
- 改名追従は対象外（見出しの改名でリンクを書き換えるのは次の段階）。

### A4. ホバープレビュー（実装済み）

**実装した内容**（`crates/app/src/hover.rs`）

- エディタ: Ctrlを押しながらリンクに乗せると、`TextEditOutput.galley.cursor_from_pos` で文字位置を求め、`editor::link_at` でリンク先を得て、
  `egui::Tooltip::always_open` で小窓を出す。`[[ノート#見出し]]` はその節（次の同じ深さ以上の見出しまで）だけを表示する。
- バックリンク・未リンクの言及・検索結果・ブックマークは `on_hover_ui` で、乗せるだけで表示（eguiのツールチップの遅延あり）。
  ファイル一覧は眺めるときに邪魔なので、Ctrlを押しているときだけ。
- 本文はfrontmatterを除いた冒頭40行まで。コードブロックの途中で切れたら閉じる。描画は本文のプレビューと同じ `preview::to_preview` + `CommonMarkViewer`
  （キャッシュは本文のプレビューと分けている）。
- プレビュー表示（`egui_commonmark` が描くリンク）へのホバー（D4 の後に追加）: egui_commonmark にはホバーを知らせる口が無いので、
  `egui_commonmark_backend` を `vendor/` に取り込み、マウスが乗っているリンクの宛先を `CommonMarkCache::take_hovered_link` で返すようにした（`[patch.crates-io]`。変更は数行、`vendor/README.md`）。

以下は着手前の設計メモ。


**狙い**: リンク先を「開かずに覗く」。行き来が減り、読む流れが切れません。

**仕様**: リンクにCtrlを押しながらカーソルを載せると、リンク先の冒頭（または指定見出しの節）を小窓で表示。

**実装**

- エディタ: `TextEditOutput` の `galley.cursor_from_pos(マウス位置 - galley_pos)` で文字位置を得て、
  既存の `editor::link_at` でリンク先を特定する。
- 表示: 補完ポップアップと同じ `egui::Area`（`Order::Tooltip`）に、`preview::to_preview` を通した本文の先頭40行ほどを
  `CommonMarkViewer` で描く。
- バックリンク欄・検索結果・ファイルツリーは自前のウィジェットなので、`response.on_hover_ui(..)` で同じ小窓を出せる。
- プレビュー側のリンクは `egui_commonmark` 内部で描かれており、ホバーを直接は取れない。
  まずエディタとサイドバーで提供し、プレビュー側は後回しにする。

### A5. 未リンクの言及（実装済み）

**実装した内容**: `Vault::unlinked_mentions` と `Vault::link_mention_text`（`crates/core/src/vault.rs`）。

- ノート名とaliasesを大文字小文字を無視して全ノートから並列に探す。長い語を優先し（「Rust」と「Rust Notes」なら後者）、
  既存のリンク（Markdownリンクは `[文字](先)` 全体）、インラインコード、コードブロック、frontmatterの中は除く。
- 英数字の語は単語の途中に当たったものを除く。日本語は単語境界を取れないので除かない。英数字3文字未満・それ以外2文字未満の名前は対象外。
- リンク化は `[[名前]]`、本文の書き方が名前と違えば `[[名前|本文の書き方]]`。同名ノートで曖昧ならパスで書く。
  書き換え前に範囲の文字列が一致するか確かめ、ずれていれば飛ばす。開いているタブはタブの本文を書き換える。
- 右サイドバーの「未リンクの言及」は折りたたみ式で、開いている間だけ計算する（索引の世代ごとにキャッシュ）。CLIは `rob mentions [--link]`。

以下は着手前の設計メモ。


**狙い**: リンクを張り忘れた言及を拾い、ワンクリックで繋ぐ。「書いたものが勝手に繋がる」体験の中心です。

**実装**

- `crates/core/src/vault.rs` に `unlinked_mentions(&self, rel) -> Vec<Mention { source, line, range }>` を追加。
  対象ノートの名前と `aliases` を `regex`（大文字小文字無視、`regex::escape` 済み）にして、全ノートの本文を
  `rayon` で並列に走査する。既存リンクの範囲（`Link.full`）、コードブロック、frontmatterは除外する。
- 日本語は単語境界が取れないので、境界判定は英数字のときだけ行う。1〜2文字の短い名前は誤検出が多いため対象外にする。
- 右サイドバーに「未リンクの言及」欄を足し、各行に「リンク化」ボタン。
  押すと該当範囲を `[[名前]]` に置き換えて `write_note` する（開いているタブがあればタブ側の本文を書き換える）。
- CLI: `rob mentions <ノート>`。

### A6. 戻る/進む・最近のファイル・ブックマーク（実装済み）

### B1. Live Preview（実装済み）

**あとから足したこと**

- **文中の画像**：行の途中の `![[pic.png]]` / `![alt](pic.png)` は、行内数式と同じ方式で表示する。
  記法の先頭の文字に、画像の幅だけ `extra_letter_spacing` を付けて場所を確保し、その上に画像を描く。
  行の高さは画像に合わせ（200pxまで）、記法を見せるときも同じ高さにする。
- **コールアウトの折りたたみ**：`[!種類]-` は閉じた状態、`+` は開いた状態で始まる。
  - 閉じた本文の行は、高さ0の極小・透明の文字にする。
  - タイトルの右の三角で開閉する。開閉の状態は（ノート, 行）ごとにアプリが覚え、ファイルは書き換えない（Obsidianと同じ）。
  - 本文にカーソルが入ったときは開いて見せる（見えない文字を編集しないように）。
- **マウスホイールのスクロール**：egui は行単位のホイール入力を0.1秒で9割進むようにならしてから適用するので、回すと遅れて動く。
  `raw_input_hook` で、ならされない8pt未満のピクセル単位の入力に分けて渡し、すぐ反映させる（動く量は同じ）。
  素早く5段回したとき、止まるまで0.2〜0.25秒かかっていたのが30ms以内になった。設定で元のなめらかな動きにも戻せる。
- **日本語と欧文のベースライン**：egui は代替フォントの文字を「そのフォントの ascent ＋ 行の高さの差の半分」に置く。
  そのため、ascent と descent の比率が欧文フォントと違う日本語フォント（游ゴシック・メイリオ・文泉驛など）では、上下にずれる。
  - epaint と同じ寸法（skrifa）をフォントファイルから読み、ファミリーの先頭のフォントとの差を `y_offset_factor` で打ち消す。
  - 日本語フォントは、ファミリーごとに別名で登録する（中身は共有）。

**狙い**: Obsidianを選ぶ最大の理由。ここが無い限り、非技術寄りの使い方では選ばれません。

**実装済みの方式**: eguiの `TextEdit` は「表示する文字列＝編集する文字列」が前提で、記法を隠す仕組みがありません。
そこで次の2つを組み合わせています（`crates/app/src/editor.rs` の `layout`、`app.rs` の `editor_ui`）。

- **畳む**: カーソルの無い行の記法文字（`#`・`**`・`[[`・`]]` など）に極小のフォントサイズ（0.01）と透明色を指定する。
  文字は残っているので、カーソル位置・選択・IMEの扱いはTextEditのまま変わらない。
- **上描きする**: 箇条書きの点、チェックボックス、引用の縦線、水平線、コードブロックの背景、表、画像は、
  対象の文字を透明にして場所だけ確保し、TextEditが返す組版結果（`galley`）から位置を求めて上（背景は下）に描く。
  画像と表は、その行の `line_height` を広げて描く場所を作っている。

記法を見せる範囲は**要素単位**です（カーソルの文字位置に触れているトークン、行頭記号、表やコードフェンス）。
カーソル位置は前フレームの値から決めるため、動かした直後の1フレームだけ表示が遅れます（直後に再描画を要求して追従させています）。
どの要素も、記法を見せるときと畳むときで行の高さが同じになるようにしてあり、テスト（`row_heights_do_not_depend_on_the_cursor`）で保証しています。

コードブロックは `syntect`（`crates/app/src/highlight.rs`）で色分けし、結果をブロック単位でキャッシュしています。

**実装した内容（第2段階）**

  `[!種類]` は要素単位で畳み、タイトルは太字・種類の色で表示。タイトルが無ければ種類名を描く。

**ブロック単位の編集**（カーソルのあるブロックだけをTextEditにする方式）は、上の方式で足りない場面が

### B2. モーダル編集（実装済み。Vim と Helix）

**Helix風**（`crates/app/src/vim/helix.rs`）: Vim のエンジンの流派として実装した。モード・選択の起点・レジスタ・`:` コマンド・Undo を共有する。
- 選択を「起点」と「頭」の2文字で持つ。ノーマルモードでは移動のたびに作り直し、`v`（SELECT）では起点を残して広げる。
- アプリは、エディタに反映した選択とそのときの頭の位置を覚えておく（`Vim::synced`）。
  - 選択がそのままなら、頭の位置を使う。変わっていれば、マウスで動かしたとみなして取り込む。
  - これは Vim のビジュアルモードの不具合の修正も兼ねる。以前は、表示上の選択の終わり（頭の次の文字）をカーソルとして読み直していたため、キーを押すたびに1文字ずつずれていた。
- マルチカーソル、`s`（選択内の正規表現）、`mi` などのテキストオブジェクトは未対応。

**Vim**:

**実装した内容**: `crates/app/src/vim.rs` に、本文（`String`）とカーソル（バイト位置）を受け取ってキーを1つずつ処理するエンジンを置いた。
GUIに依存しないので、`|` でカーソルを書いたテキストにキー列を送る形でテストしている。

- 挿入モードの文字入力は TextEdit に任せ、エンジンは Esc だけを受け取る。挿入を始めた位置と本文の長さを覚えておき、Esc の時点で
  挿入した文字列を求めて `.` の再生用に記録する（再生時だけ、エンジン自身が文字を入れる）。
- ノーマルモードでは、文字入力・Enter・Backspace・Delete・Ctrl+R/D/U・IMEの確定文字をエンジンに渡し、本文を変える他の入力は捨てる。
  矢印キーやCtrl付きのショートカット（コピーなど）はエディタにそのまま渡す。
- `u` / Ctrl+R は TextEdit の undoer をそのまま使い、エンジンの変更は1キーごとに `add_undo` で積む。
- ノーマルモードでは `PlatformOutput.ime` を消してIMEを止め、TextEdit の細いカーソルを隠してブロック型のカーソルを描く。
  TextEdit の `EventFilter.escape` を有効にして、Esc でフォーカスが外れないようにした。
- マウスで範囲を選ぶとビジュアルモードになる。`/` `n` `*` は検索バー（A7）と、`:w` `:q` は保存・タブを閉じる処理と連携する。

**未対応**: レジスタの指定（`"a`）、マクロ（`q`）、マーク（`m`）、ジャンプリスト、矩形選択（Ctrl+V）、`:s` 置換。
日本語IMEとの共存はLinuxでの動作のみ確認しており、Windows / macOS の実機確認が必要。

以下は着手前の設計メモ。


**狙い**: このプロジェクトの当初の構想（Helix / Vim の操作感）。Obsidianとの最も分かりやすい違いになります。

**実装**

- `crates/app/src/modal.rs` を新設。状態は `Mode { Normal, Insert, Visual }` と、入力途中のキー列・カウント。
- Normalモードでは、`editor_ui` の冒頭で `egui::Event::Text` と `Event::Key` をすべて取り上げ、`TextEdit` には渡さない。
  コマンドは「本文とカーソル範囲を受け取り、編集結果を返す純粋関数」として実装する（A1の `Edit` を共用）。
- 最初に入れる範囲: 移動（`h j k l w b e 0 $ gg G`）、挿入（`i a o O`）、オペレータ（`d c y` とテキストオブジェクト `iw ip`）、

### B4. プロパティの編集UI（実装済み）

**実装した内容**: `crates/core/src/props.rs` が frontmatter を `キー: 値`、`キー: [a, b]`、`キー:` ＋ `  - 項目` の形で読み、
それ以外（入れ子のマップ、複数行の文字列など）は `Raw` として元の行のまま保つ。書き戻しは該当するキーの行だけを置き換え、
必要なら値を引用符で囲む（書いた値を読み直すと同じ値になることをテストしている）。
GUIはライブ表示で frontmatter を本文から畳み（カーソルも本文の先頭より前に入らないようにする）、上に `props_ui::PropsPanel` を出す。
変更は TextEdit の undoer に積むので Ctrl+Z で戻せる。コマンド「プロパティを追加」で frontmatter が無いノートにも追加できる。
検索条件に `[キー:値]` / `[キー]` を追加。

型（D4 の後に追加）: `props::PropType`（テキスト・リスト・数値・チェックボックス・日付・日付と時刻）。Obsidian と同じ `.obsidian/types.json` を
`Vault::property_types` / `set_property_type` で読み書きし（ほかの項目は残す）、指定が無ければ `PropType::infer` で値から推測する。
欄は型ごとに、チェックボックス（`true` / `false` を引用符なしで書く `props::set_plain`）、日付のカレンダー（日本語の曜日。egui_extras の部品は英語なので自前）、
日付と時刻（カレンダーと `HH:MM` の欄）、数値（数値でなければ赤くして書き込まない）。追加のときは `Vault::property_keys` の名前を候補に出す。

### C1. 索引キャッシュと省メモリ化（差分索引は実装済み）

**実装したこと（計測してから決めた）**

1万ノート・40MB・リンク40万本の合成vaultで、どこに時間を使っているかを先に測った。

| 段階 | 変更前 | 変更後 |
|---|---|---|
| 起動（読み込み＋解析＋リンク索引） | 約290ms | 約225ms |
| 1ノート保存したときの索引更新 | 約228ms（毎回全体を作り直していた） | 1〜2ms |
| CLIの `rob stats`（プロセス全体） | 約0.52秒・最大RSS 221MB | 約0.41秒・最大RSS 199MB |

- ファイルの読み込みと解析は合わせて60ms弱で、残りはリンクの解決だった。
  なので「解析結果をディスクにキャッシュする」案は、得られても数十msなので**見送った**。
  キャッシュの不整合という新しい不具合の種を持ち込むほどの価値が無い。
- 効いたのは保存時。以前は1ノート保存するたびに全リンクを解決し直していた。
  いまは保存したノートの旧リンク先と新リンク先だけ被リンク索引を差し替える（`Vault::reindex_note`）。
  別名（aliases）が変わったときだけは他のノートのリンク先が変わりうるので全体を作り直す。
- リンク解決は、名前だけのリンク（大半）を名前・別名の表から直接引き、`a/b` のようなパス付きリンクも
  ファイル名で候補を絞ってから後方一致を見るようにした。全体の作り直しは `rayon` で並列。
- 発リンクの表は持たず、必要なときに本文の解析結果から求める。被リンクの送り元は `Arc<str>` で共有する。
- 差分更新の結果が全体の作り直しと一致することはテスト（`incremental_index_matches_full_rebuild`）で確かめている。
  計測は `ROB_BENCH_VAULT=<vault> cargo test -p robsidian-core --release --test bench -- --nocapture`。

**残り（当初案）**: 本文を常駐させない（mmap）案は、メモリが実際に問題になってから。以下は当初の案。

**狙い**: 現状は起動のたびに全ノートを読み、本文もすべてメモリに載せます。
1万ノート・40MBのvaultで約0.5秒・約340MB（リンクが極端に多い合成データでの値）。
「速くて軽い」を看板にするなら、10万ノートでも一瞬で開き、メモリも抑えたい。

  起動時は `walkdir` で一覧と更新時刻だけ取り、変わったファイルだけ読み直す。

  どちらが良いかは実測で決める（OSのファイルキャッシュが効くので、mmap + `rayon` で十分速い可能性が高い）。
- `Link` 構造体は `String` を3つ持ち、リンク数に比例してメモリを使う。本文への範囲参照に置き換えると大きく減らせる。

### C4. ユーザーコマンド（実装済み）

**実装したこと**（設定の読み込みと実行は `crates/core/src/usercmd.rs`、GUIは `crates/app/src/external.rs`）

- `replace` は、入力の末尾に改行が無ければ出力の末尾の改行を1つ落とす（`echo` などで行が割れないように）。

### C6. 関連ノートの提示（実装済み）

**実装したこと**（`crates/core/src/related.rs`）

- ノートの特徴を「つながっているノート（リンク先＋リンク元）」と「タグ」の集合とし、Jaccard係数で順位付けする。

  直接つながっているノートは、被リンク欄などで見えるので除く。
- 計算は逆向きに行う。自分のつながり先からたどって共通数を数え、候補側の次数はリンク数と被リンク数で近似する。

## 6. フェーズD: Obsidianのコアプラグインに相当する機能

Obsidianのコアプラグイン（本体に同梱され、設定で有効にする機能）を、Robsidianでも使えるようにする。
各プラグインに当たる機能が、Robsidianにすでにあるかどうかを整理した。

| 状態 | コアプラグイン |
|---|---|
| すでにある | バックリンク、ブックマーク、コマンドパレット、デイリーノート、ファイルエクスプローラー、グラフビュー、アウトライン、プロパティ、クイックスイッチャー、検索、タグ一覧、テンプレート、ページプレビュー、ファイル復元（ローカル履歴） |
| D1（実装済み） | 発リンク（画面）、単語数と選択範囲の数、ランダムノート、ユニークノート作成、スラッシュコマンド、脚注ビュー |
| D2（実装済み） | ノートコンポーザー（選択部分を別ノートに切り出す・ノートを結合する。リンクの付け替えは改名の仕組みを使う）、ワークスペース（タブと分割の配置を名前を付けて保存） |
| D3（実装済み） | Bases（プロパティを表にして絞り込む・並べ替える。クエリ（B5）を土台にする。`.base` との互換は形式を確かめてから）、スライド（`---` で区切って全画面で表示） |
| D4（実装済み） | Canvas（JSON Canvas は公開仕様。表示と編集）、音声録音（録音と保存のライブラリが要る） |
| 作らない | Web viewer（eguiにWebページを埋め込む現実的な方法が無い）、Publish・Sync（Obsidian社の有料サービス。`rob export` と git で代える）、フォーマット変換（需要が小さい） |

**オン/オフの設定**（D4 の後に追加）: 設定画面の「コアプラグイン」で、Obsidian のコアプラグインに当たる機能
（もとからあったバックリンク・ブックマーク・コマンドパレット・デイリーノート・ファイルエクスプローラー・ファイル復元・グラフビュー・
アウトライン・ページプレビュー・プロパティ・クイックスイッチャー・検索・タグ一覧・テンプレートと、D1〜D4 の機能）と関連ノート（C6）を1つずつ切り替える
（`config::Features`。古い設定ファイルでもすべてオンで始まる）。オフにした機能は、コマンド・ショートカット・表示から消し、
`.base` `.canvas` WAV は既定のアプリで開く。プレビューとエディタの組版に効くもの（Bases の展開・音声の再生ボタン）は
`preview::set_features` で知らせ、切り替えたら組版をやり直す。

**D1 で実装したこと**

- 単語数と脚注の解析は `crates/core/src/text.rs`（GUIに依存しないのでテストできる）。
  単語数は Obsidian と同じく、欧文は語、かな・漢字・ハングルは1文字を1語と数える。文字数は空白を除く。
  本文の文字数・単語数は、本文の版ごとにタブで覚えて数え直さない。
- 脚注は、行頭の `[^id]:` を定義、それ以外の `[^id]` を参照とする。コードブロックの中は数えない。
- スラッシュコマンドは、入力の直後に「行頭か空白の直後の `/`」を見つけたら、コマンドパレットを開く。
  パレットは `/` の位置を覚えておき、コマンドを選んだときだけ消す（Escなら残す）。Vimのノーマルモードでは働かない（`/` は検索）。
- ランダムノートは、乱数の代わりに時刻のナノ秒で選ぶ（依存を増やさない）。
- ユニークノートは Obsidian の既定と同じ `YYYYMMDDHHmm`。同じ名前があれば秒を足し、それでも重なれば `-2` などを付ける。

**D2 で実装したこと**

- 切り出し: 選択範囲か、カーソルのある見出しの節（次の同じか上の見出しの手前まで）を、同じフォルダの新しいノートにする。
  名前の候補は見出しの文字か最初の行（ファイル名に使えない文字は除く）。元の場所は `[[新しいノート]]` に置き換え、Ctrl+Zで戻せる。
  ダイアログを開いている間に本文が変わったら、取りやめる（本文の版で判定）。
- 結合: `Vault::merge`。改名のリンク書き換え（`Vault::retarget` に切り出した）を使い、結合元へのリンク（別名・見出し付きも）を結合先に付け替える。
  結合元の相対パスのリンクは結合先の場所から直し、結合元の frontmatter は外す。結合元はゴミ箱へ。
- ワークスペース: `.robsidian/workspace.json` に、名前ごとのタブ・選択中のタブ・分割を保存する。改名や結合のときは、中のパスも追従させる。
- あわせて直したこと
  - ダイアログを閉じた直後のフレームでは、egui が直前のモーダルより下へのフォーカスを止める。そのため、ダイアログのあとにエディタへフォーカスが戻らず、Ctrl+Zがすぐ効かなかった。モーダルが消えるまでフォーカスの要求を保留する。
  - コマンドパレットの英語の検索を、語ごとの一致にした（「open workspace」のように、キーワードが連続していなくても見つかる）。
- タスクのチェックボックス: エディタのタスク判定を一覧と同じ `core::task::task_in_line` にした。番号付き・引用やコールアウトの中・`- [ ]` だけの行、`[/]` `[-]` などの状態も描き、クリックでは Obsidian と同じく「未完了 → 完了、それ以外 → 未完了」。

**D3 で実装したこと**

- Bases（`crates/core/src/bases.rs`）: `.base` の YAML を `yaml-rust2` で読む。
  - 読むもの：`filters`（`and` / `or` / `not` の入れ子）、`views`（`type` / `name` / `order` / `sort` / `limit` / ビューごとの `filters`）、`properties` の `displayName`
  - 条件式：比較・`file.hasTag` / `inFolder` / `hasLink` / `hasProperty`・`.contains()`・`!`
  - 値は数値として読めれば数値で比べる（`pages >= 100` や評価の降順が文字列順にならないように）
  - 未対応の式はエラーとして見せる
  - 式の計算（D4 の後に追加。`crates/core/src/formula.rs`）: 字句に分けて優先順位どおりに構文を読み（Pratt 法）、値を計算する。
    条件（`filters`）と計算列（`formulas`）で同じものを使う。値は null・真偽値・数値・文字列・日付・リスト。
    関数（`if` `now` `today` `date` `number` `max` `min` など）と、型ごとのメソッド（文字列・数値・リスト・日付）、
    日付と期間の足し引き（`now() - "7d"`）、Moment.js 風の日付の書式（`YYYY-MM-DD`）。計算列どうしの参照は16段まで
  - カードのビュー（D4 の後に追加）: `type: cards`。`image`（画像のプロパティ）・`cardSize`・`imageAspectRatio`・`imageFit` を読む。
    画像は `[[x.png]]`・ファイル名・URL を受け付ける。プレビューや埋め込みでは、画像を先頭の列にした表にする
  - グループ分けと集計（D4 の後に追加）: ビューの `groupBy`（`property` と `direction`）でグループの値ごとにまとめ（値の無いものは最後の「（なし）」）、
    `summaries`（列 → `Sum` `Average` など）をグループごとに計算する（`bases::summarize`）。画面ではグループの見出しと集計の行、プレビューではグループごとの表
  - 未対応: `this`・ラムダ式。Obsidian の仕様との突き合わせはまだ（公式ヘルプをこの開発環境から読めない）
  - Obsidian の公式ヘルプ（help.obsidian.md）はこの開発環境から読めなかったので、仕様の突き合わせはまだ。互換は「主な部分のみ・未検証」
- 表示
  - `.base` ファイルを開くと表の画面（`crates/app/src/base_view.rs`）。ビューの切り替え、名前のクリックでノートを開く
  - ノートの中の ` ```base ` ブロックと `![[x.base#ビュー]]` は、プレビューで Markdown の表に展開する（クエリブロックと同じ方式）
  - 表の中のリンクに使う `[[先\|別名]]`（Obsidian の書き方）を、パーサーが読めるようにした
  - CLI は `rob base`
- スライド: `core::text::slides` で、`---` だけの行で区切る（frontmatter とコードブロックの中は除く）。
  全画面にして、プレビューと同じ描き方で文字を大きくして表示する。

**D4 で実装したこと**

- Canvas（`crates/core/src/canvas.rs`）: JSON Canvas（https://jsoncanvas.org/）を `serde_json` で読み書きする。
  - ノードは `text` / `file` / `link` / `group`、辺は `fromSide` / `toSide` / `fromEnd` / `toEnd` / `color` / `label`。色はプリセット `"1"`〜`"6"` と `#rrggbb`
  - 表示（`crates/app/src/canvas_view.rs`）: `.canvas` を開くと、最初に全体が収まるように表示する。ドラッグで移動、ホイールで拡大縮小
  - 描く順は、グループ → 辺（3次ベジェ曲線と矢印・ラベル）→ ノード。text はMarkdownの記号を除いた文、file はノートの冒頭か画像、link はURL
  - クリックで、ノートはタブで開き、それ以外のファイルは既定のアプリで、URLはブラウザで開く
  - 編集（D4 の後に追加）: カードの選択・移動（グループは中のカードごと）・大きさの変更、テキストカードとグループの名前と辺のラベルの書き換え、
    カードの追加（ダブルクリック・「カードを追加」・「ノートを追加」の窓・右クリックからグループ）、辺を引く（選んだカードの丸からドラッグ）、
    色・矢印の向き・削除（右クリック、Delete）、元に戻す / やり直す（Ctrl+Z / Ctrl+Shift+Z、100回まで）
  - 保存は操作が終わるたび。`Vault::write_file` でアトミックに書く。字下げはタブ、座標は整数（Obsidian と同じ形）。
    知らない項目（ほかのアプリが足したもの）は `extra` に取っておいて書き戻す
  - 当たり判定は カード → 辺 → グループ。グループは名前の欄と枠の近くでだけつかむ（中の空いた所のドラッグは画面の移動）
- 音声録音（`crates/app/src/recorder.rs`）: `cpal` で既定のマイクから録り、`hound` で16ビットPCMのWAVにする。
  - コマンド「録音を開始 / 停止」。録音中はステータスバーに「● 録音中 m:ss」を出し、クリックで止める
  - 止めたら `Recording 年月日時分秒.wav` を貼り付け画像と同じ添付の場所に保存し、録音を始めたノートのカーソル位置に `![[…]]` で埋め込む
  - マイクが無いときや、録音中に外されたときはメッセージを出す（外されたときは、そこまでを保存する）
  - Linux のビルドには ALSA の開発用パッケージ（`libasound2-dev`）が要る。CI とリリースのワークフローで入れる
- 音声の再生（`crates/app/src/player.rs`。D4 の後に追加）: 埋め込んだ WAV をその場で鳴らす。
  - ライブ表示では `![[x.wav]]` だけの行の下に再生ボタン（▶ / ■・経過時間・進み具合の線）を描く。プレビューでは「▶ 名前」のリンクにし、クリックで鳴らす / 止める
  - `hound` で読んで16ビットで持ち（メモリを抑える）、`cpal` で既定の出力機器へ。出力のチャンネル数と周波数には、その場で合わせる（周波数は線形補間）
  - 読み込みと再生は別スレッドで行い、長い録音でも画面を止めない。再生中はステータスバーにも出し、クリックで止める
  - 再生できるのは WAV だけ（mp3 などは、リンクのクリックで既定のアプリが開く）

## 7. フェーズE: ユーザーが作れるプラグイン

Obsidian のプラグインは JavaScript で画面（DOM）を直接いじる作りなので、同じ形は取れない。
Robsidian では **「プラグインは中身（文字・Markdown・してほしいこと）を返し、描くのと書き換えるのは Robsidian」** という形にする。
こうすると、プラグインはどの言語でも書け、ファイルの書き換えは必ず `Vault` を通る（アトミックな書き込みとローカル履歴が効く）。

方式は次の4つを比べ、外部プロセス（A）から段階的に進める。

| 方式 | 書ける言語 | 安全さ | 長所 | 短所 |
|---|---|---|---|---|
| A. 外部プロセス（ユーザーコマンドを広げる） | 何でも | 別プロセス。初回に許可を取る | 小さく始められる。CLI・MCP と同じ考え方 | 呼ぶたびに起動する（段階2で常駐させる） |
| B. スクリプト言語の組み込み（Lua / Rhai） | Lua / Rhai | 使える関数を絞れる | 入力のたびの反応も速い | 言語を選ばせる。依存が増える |
| C. WASM（Extism / wasmtime） | Rust・Go・JS など | 箱の中で動き、権限を1つずつ与えられる | 配布向き | アプリが 10MB ほど大きくなる。作る手間も大きい |
| D. Rust の動的ライブラリ | Rust | 本体と同じ権限 | 何でもできる | Rust の版が合わないと動かない。採らない |

### E1（段階1）: 外部プロセスのプラグイン（実装済み）

**置き場所と定義**: `.robsidian/plugins/<id>/plugin.toml`。`<id>` はフォルダ名（英数字・`-`・`_`）。

```toml
name = "単語の頻度"            # 表示名
version = "0.1.0"
description = "選択範囲の単語を数える"
run = "python3 main.py"        # プラグインのフォルダで sh -c（Windows は cmd /C）として実行する

[[command]]                    # コマンドパレットに出す。key でショートカットも
id = "count"
name = "単語の頻度を数える"
input = "selection"            # none / selection / note（リクエストに入れるもの）
key = "ctrl+alt+w"

[[codeblock]]                  # ```gantt のコードブロックを、プラグインが返した Markdown で描く
lang = "gantt"

[[event]]                      # ノートを保存したとき / 開いたときに呼ぶ
on = "save"                    # save / open

[[panel]]                      # 右サイドバーの欄。ノートを開いたときと保存したときに中身を作り直す
id = "summary"
title = "要約"
```

**やりとり（API 1）**: 呼ぶたびに `run` を起動し、標準入力に JSON を1つ渡し、標準出力から JSON を1つ受け取る。

```jsonc
// 標準入力（リクエスト）
{
  "api": 1,
  "kind": "command",                 // command / codeblock / event / panel
  "id": "count",                     // command・panel の id、codeblock の lang、event の on
  "vault": "/path/to/vault",
  "note": {                          // 開いているノート（無ければ null）
    "path": "日記/2026-01-31.md",
    "text": "本文すべて",              // input = "note"、event・panel のとき
    "selection": "選択範囲",           // input = "selection" のとき
    "line": 12                       // カーソルの行（1始まり）
  },
  "code": "コードブロックの中身"        // codeblock のとき
}
```

```jsonc
// 標準出力（レスポンス）。JSON でなければ、出力そのものを notice（コマンド・イベント）か
// markdown（コードブロック・パネル）として扱う（シェル1行のプラグインも書けるように）
{
  "markdown": "| 単語 | 回数 |\n|---|---|\n| a | 3 |",   // codeblock・panel の中身
  "actions": [                                            // してほしいこと（上から順に行う）
    { "type": "notice", "text": "3語ありました" },
    { "type": "replace_selection", "text": "…" },          // 選択範囲を置き換える（無ければ挿入）
    { "type": "insert", "text": "…" },                     // カーソル位置に挿入する
    { "type": "replace_note", "text": "…" },               // 開いているノートの本文を置き換える（Ctrl+Z で戻せる）
    { "type": "open", "path": "a.md" },                    // ノートを開く
    { "type": "write_note", "path": "b.md", "text": "…" }  // ほかのノートを書く・作る（Vault を通す）
  ]
}
```

**実現の方法**

- `crates/core/src/plugin.rs`（GUI 非依存。CLI と共有）
  - `Manifest`（serde + toml、`deny_unknown_fields`）と `discover(root)`：フォルダを見て、読めたものと読めなかったもの（理由つき）を返す
  - `Request` / `Response` / `Action`（serde）と `execute(plugin, &Request)`：`usercmd::execute` と同じく `sh -c` で起動し、
    標準入力は別スレッドで書く。環境変数 `ROB_VAULT` `ROB_NOTE` `ROB_PLUGIN_DIR` も渡す。
    30秒で打ち切る（終わらないプラグインで固まらないように）。標準出力が JSON でなければ平文として扱う
  - `write_note` のパスは vault の中だけ（`Vault::write_note` の検査に任せる）
- `crates/app/src/plugins.rs`
  - 一覧の読み直し（`plugin.toml` の更新時刻を1秒ごとに見る。ユーザーコマンドと同じ）
  - 許可：初めて実行するとき（と `plugin.toml` が変わったとき）に、`plugin.toml` の中身を見せて許可を取る。
    許可は vault の外（アプリの設定）に、vault とプラグインの id ごとに内容と一緒に記録する（ユーザーコマンドと同じ考え方）。
    実行するスクリプトの中身までは見ないので、他人の vault のプラグインは中身を確かめてから許可するよう画面に書く
  - 実行は別スレッド（`Job`）。結果は次の描画で反映する。頼んだときのノートと版を覚えておき、編集が進んでいたら置き換えはしない
  - コードブロック：プレビューの変換の後で、登録された言語のブロックを結果の Markdown に置き換える（Mermaid と同じ作り）。
    結果は (プラグイン, 言語, 中身のハッシュ) で覚え、実行中は「実行中…」、未許可なら許可の手順を出す
  - イベント：保存・開いたときに呼ぶ。プラグインの書き換えで保存したときは、保存のイベントをもう一度は呼ばない（無限に続かないように）
  - パネル：右サイドバーに欄を足し、ノートを開いた・保存したときに作り直す
  - 設定画面に「プラグイン」の欄：一覧・説明・オン/オフ・許可の取り消し・読めなかった理由
- CLI：`rob plugin list`（一覧と読めなかった理由）と `rob plugin run <id> <command|codeblock|panel|event> <名前> [--note ノート] [--code 中身]`
  （画面なしでプラグインを試せる。返した JSON をそのまま出す）
- 例：`examples/plugins/` に、シェルだけのもの（単語数）と Python のもの（コードブロックを表にする）を置き、README に書き方を書く

**実装したときに決めたこと**: 許可はユーザーコマンドと同じ `trusted_commands` に `plugin:<vault>#<id>` のキーで記録し、オフにしたものは
`disabled_plugins` に入れる。許可していないプラグインのコードブロックは実行せず、許可の手順を出す。パネルは右サイドバーを出しているときだけ作る。
`replace_selection` と `insert` はコマンドでだけ使える（イベント・パネルでは選択範囲が決まらないため）。

**段階1でしないこと**: プラグインからの問い合わせ（ほかのノートを読む・検索する）は段階2。プラグインの画面（入力欄・ボタン）は持たない
（入力が要るときは、選択範囲やコードブロックで渡す）。

### E2（段階2）: 常駐するプラグインと、Robsidian に問い合わせる口

- `plugin.toml` に `mode = "server"` と書いたプラグインは、起動したままにして JSON-RPC 2.0（行区切りの JSON。LSP と同じ考え方）で話す。
  起動は1回で済み、状態も持てる。リクエストの形は段階1と同じものを `method` で呼び分ける
- プラグインから Robsidian への問い合わせ：`vault/read` `vault/search` `vault/backlinks` `vault/write`（書き換えは `Vault` を通す）。
  中身は MCP サーバー（`crates/cli/src/mcp.rs`）の道具とほぼ同じなので、処理を core に寄せて共有する
- 入力のたびの補完（`completion`）や、パネルの随時更新（プラグインからの通知）もここで足す

### E3（段階3）: WASM のプラグインと配布

- 配って使ってもらうなら、WASM（Extism）で動かし、`plugin.toml` に書いた権限（`read` / `write` / `network`）だけを与える
- プラグインの一覧（git のリポジトリに置いた JSON）から、検索して入れられるようにする
- 段階1・2のやりとり（JSON の形）はそのまま使い、WASM でも外部プロセスでも同じプラグインの書き方にする
